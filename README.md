## How I build

- Start with a concrete engineering problem.
- Prefer the simplest architecture that satisfies the requirements.
- Test failure paths, not only happy paths.
- Measure before making performance claims.
- Treat security and resource limits as design constraints.
- Document trade-offs and known limitations.
- Keep public claims aligned with repository evidence.
- Iterate through **BUILD → TEST → MEASURE → DOCUMENT → DEPLOY → REVIEW → IMPROVE**.
